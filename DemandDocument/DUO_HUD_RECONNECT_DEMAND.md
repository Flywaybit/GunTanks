# GunTanks 双人对战贴图、HUD 与断线重连需求

## 1. 目标

修复双人在线对战中的以下问题：

1. 地图只有棕色地形轮廓，没有原版地图贴图。
2. 按 `1/2/3` 选择武器后，左下角武器 HUD 不更新。
3. 按 `W/S` 调整发射角度后，角度 HUD 不更新。
4. 关闭网页、网络波动或延迟导致 WebSocket 断开后，Redis 仍残留在线状态，重新登录显示 `ALREADY_ONLINE`。
5. 断线后对局没有暂停，回合倒计时、移动、瞄准和发射仍可能继续。
6. 重连后应恢复原对局，不得进入大厅。

本需求只针对当前双人匹配在线模式。原版 `C:\GoProject\GunTanks\Guntanks` 仍是战斗表现和操作规则基准。

## 2. 已确定规则

### 2.1 主动退出与异常断线

- 玩家在对局中主动点击 `Leave`，才算主动退出。
- 主动退出立即判该玩家负，对手获胜。
- 主动退出必须结束双方对局，双方客户端都离开战斗页面并进入结果页面。
- 主动退出不得创建重连资格，不得进入 `RECONNECTING`。
- 关闭网页、刷新网页、浏览器休眠、网络波动、连接超时、WebSocket 异常关闭，都属于异常断线，不算主动退出。
- 异常断线后，掉线玩家获得 60 秒重连时间。
- 每次新的异常断线都重新获得完整 60 秒重连时间，采用 `1A 2A` 决策。
- 60 秒内未恢复到原对局，服务端判掉线玩家负，对手获胜。
- 重连成功后必须回到原 `battle_id`，不得回大厅，也不得创建新对局。

### 2.2 断线暂停

任意一名玩家异常断线后，对局立即进入暂停状态：

- 服务端停止对局 Actor 的游戏逻辑推进。
- 停止 30 秒回合倒计时，保存剩余时间，不重新计算整回合时间。
- 停止移动、瞄准、武器选择、蓄力和发射处理。
- 在线玩家不能通过旧连接或新消息继续操作。
- 不推进风力、弹体运动、碰撞、伤害、地形破坏、回合切换和动画状态。
- 双方客户端显示“等待对手重连”和剩余重连时间。
- 只有掉线玩家成功重连并完成状态同步后，才恢复倒计时和操作。
- 60 秒超时判负时，先恢复 Actor 的终止处理，再发送最终结果。

## 3. 地图贴图修复

### 3.1 当前原因

`guntanks-client/src/renderer.js` 在加载服务端地形快照后，将 `terrainLayer` 清空并通过 `ImageData` 填充固定的棕色像素。该快照只有地形实心/空洞信息，不包含原版纹理，因此会覆盖 `assets/terrain-full.png` 的真实贴图。

### 3.2 实现要求

- 地图视觉必须继续使用 `guntanks-client/assets/terrain-full.png`，不得用纯棕色像素替代原版贴图。
- 服务端快照中的 bitset 只作为权威碰撞和可见地形遮罩。
- 客户端先绘制原版地形贴图，再按照服务端 bitset 清除已经被破坏的区域。
- 初始地图的坐标、尺寸和偏移必须与服务端 `LoadTerrainPNG(..., 1200, 650, 50, 320)` 完全一致。
- 炮弹爆炸后，客户端只应用服务端下发的破坏圆心和半径，不能自行推测不同的地形结果。
- 重连、刷新和重新加载快照后，纹理和地形空洞必须与断线前一致。
- 快照加载、校验和应用完成前，禁止玩家输入和发射。
- 快照加载失败必须显示明确错误并阻止进入可操作战斗，不能静默显示错误地图。
- 地图背景、地形纹理、坦克贴图、瞄准指示器的视觉效果不得被新的同步方案改变。

## 4. 武器 HUD 修复

### 4.1 权威状态

服务端 `engine.Tank.Weapon` 和 `SSCooldown` 是唯一权威来源。客户端不能只依赖按键本地状态。

每次以下事件后，服务端必须广播包含完整最新战斗状态的事件：

- `battle.select_weapon` 成功。
- 发射完成。
- 回合切换。
- 重连快照。
- `battle.resync`。

状态中的当前玩家 Tank 必须能稳定映射到当前用户，不能因为后续 `battle.tank_state` 或 `battle.snapshot` 替换状态而丢失 `my_tank_id`。

### 4.2 客户端显示

- 按 `1` 发送 `battle.select_weapon { weapon: "shell1" }`。
- 按 `2` 发送 `battle.select_weapon { weapon: "shell2" }`。
- 按 `3` 发送 `battle.select_weapon { weapon: "ss" }`。
- 服务端确认成功后，左下角 HUD 立即按照当前 Tank 的 `weapon` 更新。
- `shell1`、`shell2`、`ss` 的选中灯、未选中灯和冷却状态必须与原版一致。
- 非当前回合、对局暂停、炮弹动画播放期间，武器选择输入必须被阻止或明确显示不可操作。
- 服务端拒绝选择时，客户端不得改变 HUD；应保留最后一次有效武器状态并显示错误。
- SS 发射后必须按原版规则进入冷却，并在服务端状态确认后切回普通炮弹显示。

## 5. 角度 HUD 与瞄准状态

- `W/S` 仍是唯一的角度控制键，不新增上下左右或 Fire 按钮。
- 服务端角度按原版规则每次调整 `2` 度，并循环归一化到 `[0, 360)`。
- 客户端 `angle-display` 必须显示当前玩家 Tank 的最新权威角度，不能固定为 `0` 或使用旧状态。
- 每次 `battle.aim_start`、`battle.aim_stop`、回合切换、重连快照和状态同步后，都要刷新角度文本。
- 调整角度期间，画布中的发射指示器也必须同步使用最新角度。
- 发射指示器必须复刻 `Guntanks/lib/tank.js`：
  - 外层灰色圆弧：半径 `50`，角度范围 `+/-20` 度。
  - 中层红色圆弧：半径 `50`，角度范围 `+/-5` 度。
  - 内层红色圆弧：半径 `45`，角度范围 `+/-2` 度。
  - 左朝向必须使用原版 `180` 度方向转换和圆心偏移。
- 角度可以连续旋转超过 90、180 和 270 度，不能恢复为 `-90..90` 限制。

## 6. 在线状态与会话接管

### 6.1 Redis 状态

在线状态和重连状态必须分开管理，但二者生命周期必须由同一个用户会话和对局状态协调：

- `online` 记录当前有效会话和连接代数。
- `reconnect` 记录用户可恢复的 `battle_id`、断线时间和过期时间。
- 所有释放操作必须校验 `user_id + session_id/generation`，旧连接不能删除新连接的在线 key。
- 对局异常断线时，不能只留下无法被登录流程识别的 `online key`。
- 对局异常断线时，应创建 60 秒重连记录，并使该账号能够通过认证接管旧会话。
- 对局外关闭网页或大厅断线时，应及时释放在线 key，避免普通登录长期显示已在线。
- 主动 Leave、正常结算、注销和服务端关闭都必须清理该用户的重连记录。

### 6.2 登录接管决策

采用 `1A`：

- 登录先验证用户名和密码。
- 如果账号没有有效对局，已有在线会话仍按普通重复登录处理，返回 `ALREADY_ONLINE`。
- 如果账号存在未结束且处于 60 秒重连窗口的对局，允许本次新登录接管旧会话。
- 接管时生成新的 `session_id`/连接代数，并原子替换 Redis 在线租约。
- 旧 WebSocket 连接必须被标记为失效并关闭。
- 旧连接的清理回调不得删除新会话的在线 key，也不得覆盖新的 reconnect 记录。
- 新客户端建立 WebSocket 后，服务端必须根据用户身份找到原 `battle_id`，发送 `reconnect.accepted` 和完整 `battle.snapshot`。
- 登录接管不得创建新战斗、重复结算或重复写入对局记录。
- 如果 60 秒已过期，登录不能恢复原对局，应返回对局已结束/重连已过期，并清理残留状态。

## 7. 服务端重连状态机

建议状态：

```text
PLAYING
  -> PAUSED_DISCONNECTED  异常 WebSocket 断开
  -> FINISHED             主动 Leave、正常结束、重连超时

PAUSED_DISCONNECTED
  -> PLAYING              原玩家在 60 秒内完成接管和 resync
  -> FINISHED             60 秒超时判负
```

要求：

1. 进入 `PAUSED_DISCONNECTED` 必须记录暂停时刻和每个玩家的剩余回合时间。
2. 暂停状态下所有战斗命令返回可识别的 `BATTLE_PAUSED`，不得改变战斗状态。
3. 重连必须校验用户确实属于该 `battle_id`，不能仅凭客户端传入的战斗编号恢复。
4. 重连完成前先发送完整战斗状态和地形快照，再发送暂停结束/恢复事件。
5. 只有服务端确认双方状态同步完成后，才恢复 Actor tick。
6. 恢复时将原剩余回合时间加到当前服务器时间，不能把 30 秒倒计时重新开始。
7. 重连计时器必须幂等，同一用户快速断开和重连不能创建多个判负任务。
8. 重连成功后取消该用户旧的超时判负任务。
9. 超时判负、主动 Leave 和正常结算都必须只执行一次。

## 8. 客户端状态机

- 异常断线且 `store.battle` 属于未结束对局时进入 `RECONNECTING`，不能进入 `LOBBY`。
- `RECONNECTING` 页面显示 60 秒窗口的剩余时间。
- 重连期间清空键盘按下状态、停止蓄力动画、禁用 Leave 以外的战斗操作。
- 收到 `reconnect.accepted` 后请求/接收战斗快照和地形快照。
- 两个快照应用完成后回到 `BATTLE`，恢复 HUD 和倒计时。
- 收到重连超时、战斗已结束或会话接管失败时，清理战斗状态并进入 `RESULT` 或 `LOBBY`，不得无限显示 `Connection lost. Reconnecting...`。
- 主动 Leave 后设置不可重连标记；任何旧连接关闭事件都不能把页面切换到 `RECONNECTING`。
- 刷新页面后，如果 token 仍有效且账号有可恢复对局，登录初始化必须直接进入重连流程并恢复该对局。

## 9. 建议改动范围

客户端重点检查：

- `guntanks-client/src/renderer.js`：纹理与权威地形遮罩合成、快照失败处理。
- `guntanks-client/src/main.js`：玩家 Tank 身份保持、HUD 刷新、重连页面和事件路由。
- `guntanks-client/src/inputController.js`：暂停/动画期间禁用输入、断线时清零蓄力。
- `guntanks-client/src/socket.js`：连接代数、旧连接失效、重连调度和主动关闭区分。
- `guntanks-client/src/store.js`：battle identity、重连状态、主动 Leave 标记清理。

服务端重点检查：

- `guntanks-server/web/ws.go`：连接所有权、断线原因判定、重连记录和旧连接关闭。
- `guntanks-server/battle/manager.go`：暂停/恢复、重连快照、超时任务和用户接管。
- `guntanks-server/battle/actor.go`：暂停时停止 tick 和倒计时，恢复时继续剩余时间。
- `guntanks-server/engine/engine.go`：武器、角度和战斗状态字段必须完整广播。
- `guntanks-server/redis/presence.go`、`redis/client.go`：增加原子接管、租约校验和重连记录清理。
- `guntanks-server/main.go`：登录、注销和会话接管分支。

## 10. 测试与验收

### 10.1 自动化测试

- 地形快照应用后仍显示 `terrain-full.png` 原始纹理，破坏区域透明。
- 快照与破坏事件按顺序应用后，客户端和服务端地形 mask 一致。
- `1/2/3` 成功更新当前 Tank 的武器 HUD；非法或冷却选择不改变 HUD。
- `W/S` 可验证角度经过 90、180、270 度并正确循环。
- 异常断线使 Actor、倒计时和命令处理暂停。
- 重连成功恢复同一 `battle_id`、回合、角度、武器、血量、地形和剩余倒计时。
- 每次异常断线重新拥有 60 秒；超时只结算一次。
- 主动 Leave 立即判负且不生成 reconnect key。
- 旧连接清理不能删除新会话的在线 key。
- 有效重连对局可以通过新登录接管；普通无对局重复登录仍返回 `ALREADY_ONLINE`。

### 10.2 双浏览器验收

1. 两个账号进入双人匹配并开始对局。
2. 在当前回合按 `1`、`2`、`3`，确认左下角选中状态实时变化。
3. 按住 `W/S`，确认角度文本、360 度指示器和发射方向同步变化。
4. 发射炮弹并破坏地形，确认双方看到原版纹理和一致的地形缺口。
5. 关闭一方网页，确认双方进入暂停，30 秒倒计时停止，在线方无法移动或发射。
6. 60 秒内重新登录，确认直接恢复原对局，不能进入大厅，恢复后倒计时从断线前剩余时间继续。
7. 重连后再次关闭网页，确认重新获得完整 60 秒窗口。
8. 关闭网页后立即重新登录，确认不再因旧 Redis key 错误显示 `ALREADY_ONLINE`。
9. 在对局内点击 `Leave`，确认立即判负、双方结束对局，且刷新后不会进入重连页面。
10. 检查 Redis，确认正常结束后没有残留 `online` 或 `reconnect` key。

### 10.3 构建要求

- 执行 `go test ./...`。
- 执行客户端构建和 JavaScript 语法检查。
- 重新构建 `C:\GoProject\GunTanks\guntanks-server\guntanks-server.exe`，不能使用旧可执行文件测试。
- 浏览器测试必须使用最新构建资源并执行硬刷新，排除旧缓存影响。

## 11. 完成标准

只有同时满足以下条件才算完成：

- 双人对战地图视觉与原版贴图一致，破坏区域和服务端地形一致。
- 武器、角度、发射指示器和蓄力状态实时正确。
- 异常断线完全暂停对局，60 秒内可恢复原对局。
- 每次异常断线都重新获得完整 60 秒。
- 主动 Leave 立即判负且永不进入重连。
- Redis 在线状态不会阻塞有效对局接管，也不会留下普通登录的脏锁。
- 自动化测试、双浏览器测试和最新服务端构建全部完成。
