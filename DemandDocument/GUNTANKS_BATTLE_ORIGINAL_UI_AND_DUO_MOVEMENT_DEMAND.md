# GunTanks 原版战斗界面与双人移动修复需求

## 1. 目标

以 `C:\GoProject\GunTanks\Guntanks` 为唯一战斗界面和战斗逻辑基准，修复当前联网客户端与原版行为不一致的问题，并修复双人匹配中无法移动的 Bug。

本需求只涉及战斗页面、战斗输入、战斗逻辑兼容和中途退出；不引入新的战斗按钮或新的战斗操作方式。

## 2. 原版完全复刻要求

### 2.1 界面

- 对战页面的布局、Canvas 分层、控件样式、文字、图片、音频、动画和交互必须完全复刻 `Guntanks` 原版。
- 删除战斗页面中的 `Guntanks!` 字样。
- 不得新增“上移、下移、左移、右移、Fire、发射”等按钮。
- 不得用新的按钮界面替代原版键盘操作。
- 原版已有的武器选择、力度条、SS 状态、风向风速、回合队列、倒计时和声音效果必须保留并按原版显示。

### 2.2 键盘输入

必须按原版键位工作：

- `A`：向左移动。
- `D`：向右移动。
- `W`：提高炮管角度。
- `S`：降低炮管角度。
- `1`：选择第一种炮弹。
- `2`：选择第二种炮弹。
- `3`：选择 SS 炮弹，必须遵守原版冷却规则。
- 空格按下开始蓄力，空格释放发射。

战斗页面不得使用方向键、独立移动按钮或独立 Fire 按钮替代上述操作。输入仍需经过客户端状态和当前回合权限检查，但不能改变原版按键含义。

### 2.3 战斗逻辑

以下逻辑必须以 `Guntanks` 为基准保持一致：

- 坦克移动、移动距离上限、贴地、下落和地形碰撞。
- 炮管角度变化、面向方向和炮弹发射位置。
- 三种炮弹的速度、重量、伤害、爆炸半径、颜色和 SS 冷却。
- 炮弹飞行轨迹、风力影响、重力、坦克碰撞和地形碰撞。
- 爆炸破坏地形、坦克受伤、坦克死亡和回合切换。
- 回合顺序、回合倒计时、delay、换风时机和最终胜负。

服务端仍然是权威判定者；客户端只负责复刻原版输入和画面，并播放服务端返回的权威结果。不得因为联网改造而增加范围伤害、修改数值、改变物理公式或改变操作手感。

## 3. 战斗中途退出

- 战斗页面保留中途退出入口，但该入口不能改变原版战斗控制布局；应使用现有页面中合理的退出位置或最小化的退出交互。
- 玩家确认退出后只发送一次 `battle.leave`。
- 服务端收到 `battle.leave` 后立即将该玩家判定为淘汰/认输，自动判负。
- 如果退出后只剩一名存活玩家，立即结算剩余玩家获胜。
- 退出请求发送成功或收到服务端淘汰/结算事件后，客户端停止键盘监听、蓄力动画、战斗动画和战斗定时器，进入结算页面。
- 退出请求失败时不得伪造结算结果；恢复战斗输入并显示错误。
- 关闭网页导致 WebSocket 断开时，按既定断线重连规则处理；主动退出和浏览器关闭不得混为同一个客户端动作。

## 4. 双人匹配无法移动 Bug

### 4.1 现象

双人匹配进入战斗后，玩家可以选择武器和开炮，但按移动键无法移动；调角输入也可能受到同一问题影响。

### 4.2 已确认原因

当前 `guntanks-client/src/inputController.js` 的 `handleKeyDown()` 执行顺序存在错误：

```js
store.input[mapped.kind === 'move' ? 'moveDirection' : 'aimDirection'] = mapped.direction;
startAxis(mapped.kind, mapped.direction);
```

`startAxis()` 内部会检查当前方向是否已经相同：

```js
if (store.input[field] === direction) {
  return true;
}
```

因此 `handleKeyDown()` 先写入方向，`startAxis()` 随即认为该方向已经启动并直接返回，导致 `battle.move_start` 或 `battle.aim_start` 没有发送给服务端。服务端的 `engine.Move()` 和 `battle.Actor` 本身支持双人局移动，根因在客户端输入控制器的状态写入顺序，不是双人匹配规则限制移动。

### 4.3 修复要求

- `handleKeyDown()` 不得在调用 `startAxis()` 前直接写入 `moveDirection` 或 `aimDirection`。
- 由 `startAxis()` 统一完成“检查重复、发送 start、写入本地 held 状态”。
- 首次按下 `A/D/W/S` 时必须分别发送一次：
  - `A/D -> battle.move_start {direction:left/right}`
  - `W/S -> battle.aim_start {direction:up/down}`
- 重复 `keydown`、浏览器按键自动重复和重复指针事件不得重复发送 start。
- 释放按键时分别发送一次 `battle.move_stop` 或 `battle.aim_stop`。
- `keyup`、`blur`、`visibilitychange(hidden)`、`pagehide`、`pointercancel` 和页面切换都必须清理输入并发送必要的 stop。
- 修复后必须验证 2 人、3 人、4 人匹配中的移动和调角行为一致。

推荐修复逻辑：

```js
if (store.input.heldKeys.has(event.key)) return;
store.input.heldKeys.add(event.key);
startAxis(mapped.kind, mapped.direction);
```

不要在 `startAxis()` 外部提前写入方向状态。

## 5. 客户端改造约束

- 不得继续使用上一份 UI 重构需求中新增的方向键、移动按钮和 Fire 按钮；战斗页面以本需求覆盖之前的相关冲突要求。
- 登录、大厅、匹配、结算和重连页面可以保持状态隔离，但进入战斗后必须使用原版战斗页面。
- 客户端不得自行计算命中、伤害、死亡、地形结果或胜负。
- 服务端返回的弹道、命中、伤害、地形破坏和坦克状态必须转换为原版画面效果。
- 不得为了修复移动 Bug 而放宽服务端回合校验；只有当前坦克的玩家可以移动、调角和发射。

## 6. 测试与验收

- 对战页面视觉上与 `Guntanks` 原版一致，且不显示 `Guntanks!`。
- 战斗页面不存在上下左右、移动和 Fire 等新增操作按钮。
- `A/D/W/S/1/2/3/空格` 按键行为与原版一致。
- 双人匹配中当前玩家可以移动、调角和开炮；对手的坦克不能被本地输入控制。
- 三人、四人匹配中的移动和调角行为正常。
- 首次按键发送一次 start，重复 keydown 不重复发送；释放发送一次 stop。
- 失焦、隐藏页面、取消指针和离开战斗后不会残留移动或调角状态。
- 三种炮弹、风、弹体运动、碰撞、地形破坏、伤害、死亡和回合切换与原版基准一致。
- 玩家主动退出后自动判负，剩余玩家正确获胜并进入结算。
- 前端构建通过，浏览器控制台无未处理异常，服务端既有战斗测试继续通过。
