# GunTanks 刷新重连、战斗还原与模式调整需求

## 1. 目标

本次修改同时完成以下事项：

1. 修复在线对局中刷新网页后持续显示 `Connection lost. Reconnecting...` 的问题。
2. 在线双人对战的地形、移动、瞄准、武器选择、力度条和发射指示器必须与原版 `C:\GoProject\GunTanks\Guntanks` 一致。
3. 删除 3 人、4 人匹配，仅保留双人匹配。
4. 新增单人模式：一个本地玩家依次操纵 4 辆 Tank，完整复用原版规则；该模式不产生任何战绩和数据库记录。

除网络同步和主动退出外，不得自行简化或重新设计原版战斗规则与战斗 UI。

## 2. 已确认问题及原因

### 2.1 刷新后持续重连

该问题存在。

- 登录令牌保存在 `sessionStorage`，刷新后新页面会使用同一个 `session_id` 建立新 WebSocket。
- `web/ws.go` 在每条 WebSocket 连接退出时都调用 `ReleaseOnline(userID, sessionID)`。
- 新旧连接使用相同的在线租约值。刷新过程中，新连接可能已经刷新租约，但旧连接随后仍能删除这份租约；也可能旧连接先删除租约，导致新连接握手时 `RefreshOnline` 失败。
- 客户端把该非主动关闭统一视为网络断线并无限重试，因此停留在 `Connection lost. Reconnecting...`。
- 服务端当前没有“同一会话的新连接已接管旧连接”的原子所有权判断，也没有覆盖刷新竞态的端到端测试。

### 2.2 地形破坏后移动不符合新地形

该问题存在，包含服务端逻辑和客户端恢复两部分缺陷。

- `engine.State.Move` 只修改 Tank 的 `X` 和朝向，不读取 `TerrainMask`，也不更新 `Y`。
- `battle.Actor.tick` 调用上述纯水平移动，不执行原版的侧面阻挡、上坡修正、脚下支撑检测和下落逻辑。
- 炮弹会正确修改服务端 `TerrainMask`，但 Tank 后续移动没有使用修改后的地形。
- 客户端只在当前内存中的 `terrainLayer` 挖洞，从未请求或解码 `terrain-snapshot`。刷新或重连后会重新绘制完整地形，历史破坏全部丢失。

### 2.3 瞄准范围和发射指示器错误

该问题存在。

- 服务端 `Aim` 把角度限制为 `-90..90`，原版 `Tank.changeAngle` 没有该限制，角度可以连续旋转。
- 当前渲染器只画一段约 `±8°` 的灰色圆弧。
- 原版右朝向指示器包含 `±20°` 灰色弧、`±5°` 红色弧和 `±2°` 的内层红色弧；左朝向还需使用原版的锚点和 `180°` 朝向换算。

### 2.4 Angle 和武器 UI 不更新

该问题存在。

- `my_tank_id` 只在 `battle.started.payload.players` 中由客户端临时写入初始 state。
- 后续 `battle.tank_state` 是新的纯服务端 state，不包含 `players` 或 `my_tank_id`，会覆盖 `store.battle`。
- 从此客户端无法稳定找到本机 Tank，`angle-display` 和武器选中灯不会再更新。
- 键盘 `1/2/3` 已发送 `battle.select_weapon`，服务端也会产生状态事件，主要缺陷是客户端玩家身份映射丢失及 HUD 未按原版状态渲染。

### 2.5 力度条释放后不清零

该问题存在。

- `commitFire` 在松开空格后再次调用 `updatePower(power)`，明确保留本次力度。
- 初始值仍是 `60%`，清理输入状态时也没有同步清空 DOM。
- 正确行为是按住空格时从 0 增长，松开后立即提交本次力度并把可见填充和显示值归零；下一次蓄力必须重新从 0 开始。

## 3. 刷新和重连修复

### 3.1 服务端连接所有权

在 Gateway 中为每个 WebSocket 分配唯一 `connection_id`，并维护线程安全的当前连接所有权：

```text
user_id + session_id -> current_connection_id
```

要求：

1. 新连接注册时原子接管同一用户、同一会话的旧连接。
2. 旧连接的 defer 只有在其仍是当前所有者时才允许释放在线租约和创建断线重连状态。
3. 已被新连接替代的旧连接退出时，不得删除在线租约、不得覆盖 reconnect key、不得启动 60 秒淘汰计时器。
4. 为兼容页面关闭后及时下线，可在当前连接断开后延迟 1 至 2 秒释放租约；延迟任务执行前必须再次确认没有同会话替代连接。
5. `RefreshOnline` 返回 `false` 时不得忽略。当前连接应收到明确的会话失效关闭码并停止作为有效连接工作。

不得仅依靠 `pagehide/beforeunload` 发送消息判断刷新，因为浏览器不保证该消息送达。正确性必须由服务端连接所有权保证。

### 3.2 对局恢复顺序

在线双人对局刷新后必须按以下顺序恢复：

1. `/api/v1/me` 验证现有 token。
2. 建立新 WebSocket，新连接接管旧连接。
3. 收到 `hello` 后，如用户仍在有效对局，服务端发送 `reconnect.accepted`。
4. 客户端请求或接收权威 battle snapshot 和最新 terrain snapshot。
5. 两份快照均应用完成后发送 `battle.resync_ack`，再进入 `BATTLE` 并解锁输入。

恢复期间只能显示一次 `RECONNECTING`，不得反复在 `LOBBY/RECONNECTING/BATTLE` 间切换。对局已结束时应清理本地战斗状态并进入结果页或大厅，不得无限重试。

## 4. 地形和移动完全还原

### 4.1 服务端权威移动

在线模式仍由服务端权威计算，不能把碰撞判定交还客户端。将原版 `Tank.move` 的规则移植到 Go 引擎，并统一使用战斗当前的 `TerrainMask`：

- Tank 碰撞尺寸、坐标含义和原版保持一致。
- 左右移动前检查对应方向的侧面地形，不得穿墙。
- 水平移动后如底部与地形相交，逐像素向上修正，复刻原版上坡行为。
- Tank 脚下失去支撑时按原版速度下落；地形被炸毁后，即使玩家没有按移动键，也必须在服务端 tick 中下落并重新落地。
- 每回合最大移动距离仍为原版的 80，移动速度仍为每 tick 1.5。
- Tank 掉出地图后按原版淘汰逻辑处理。
- 初始 Tank 的 `Y` 必须通过同一 TerrainMask 落地计算，不能继续固定为与地形无关的 `300`。

所有位置变化必须通过 `battle.tank_state` 广播。客户端只渲染权威坐标，不自行预测并写回最终坐标。

### 4.2 客户端地形同步

实现统一的 terrain state：

1. 初次进入、刷新重连和事件序列不连续时，读取 `terrain_snapshot.href` 或 `/api/v1/battles/{id}/terrain-snapshot`。
2. 解码 `data_base64`，校验 `encoding`、`checksum`、宽高和 `snapshot_seq`，生成客户端碰撞/绘制用 mask。
3. 应用快照之后，只顺序应用 `snapshot_seq` 之后的 `terrain_destroyed` 事件。
4. 同一破坏事件必须按 `event_seq` 幂等处理，不能重复挖洞。
5. terrain snapshot 未完成前禁止播放后续战斗和开放输入。
6. 重连后画面中的洞必须与服务端炮弹碰撞和 Tank 落地使用的 mask 一致。

## 5. 角度、武器和 HUD 还原

### 5.1 角度

- 删除服务端 `-90..90` 限制，按原版每 tick 增减 `2°`。
- 物理计算和 Canvas 绘制均支持完整 360° 周期，不得只支持半圆。
- `angle-display` 实时显示当前操纵 Tank 的最新权威角度，显示规则与原版一致。
- `W/S` 松开后必须发送 aim stop；切回该玩家回合时不得残留上回合按键状态。

### 5.2 发射指示器

逐项复刻 `Guntanks/lib/tank.js`：

- 右朝向：以原版 Tank 坐标为圆心，绘制灰色 `±20°` 外弧、红色 `±5°` 中弧、红色 `±2°` 内弧。
- 左朝向：使用原版 `x + 20` 圆心及 `angle + 180°` 换算。
- 弧线半径、颜色、透明度、线宽和绘制层级与原版一致。
- 不得用当前单段灰色圆弧替代。

### 5.3 稳定的玩家-Tank 映射

新增独立于 battle state 的只读身份数据，例如：

```text
store.battleIdentity = { battleId, myTankId, playersByTankId }
```

- 仅由 `battle.started.players` 或重连快照中的玩家映射初始化。
- `setBattle` 更新权威 state 时不得清除该映射。
- 所有 HUD、输入权限和结果判断都从该映射获得 `myTankId`。
- 服务端重连 snapshot 必须提供恢复该映射所需的玩家列表，不能依赖刷新前的内存。

### 5.4 武器选择

- 按 `1/2/3` 后，由服务端确认选中状态，再更新左下角对应灯。
- Shot 1、Shot 2 选中灯为绿色；SS 选中灯为红色，其他灯为原版灰色。
- SS 冷却期间保持原版不可选视觉和输入规则；发射 SS 后自动回到 Shot 1。
- HUD 以当前操纵 Tank 的 `weapon` 和 `ss_cooldown` 为唯一权威数据，不维护另一套易漂移的选中状态。

### 5.5 力度条

- 初始填充为 0，不能是 60%。
- 按住空格后从 0 连续增长到 100%，增长速度与原版一致。
- 松开空格时先保存本次 power 并发送 `battle.fire`，随后立即将可见填充和文本归零。
- 发送失败、失焦、切页、断线、回合变化和战斗结束均必须停止动画并归零。
- 保留原版上一发力度标记时，应使用独立的 `previousPower` 标记线，不能通过让当前填充停留在旧值实现。

## 6. 模式调整

### 6.1 大厅入口

大厅仅保留两个入口：

- `Single Player`
- `2 Player Match`

删除 3 人和 4 人匹配按钮、队列、提示文案以及可被客户端调用的对应匹配分支。房间功能继续维持此前的暂缓状态，不在本次恢复。

### 6.2 双人匹配

- `match.join.player_count` 只接受 `2`。
- Lobby 只维护双人队列；服务端收到 3 或 4 必须返回明确的 `INVALID_ARGUMENT`。
- `battle.Manager.Create` 的在线匹配入口只创建两名真实玩家的战斗。
- 清理和更新所有仍声称支持 `2..4` 的配置、接口校验、文档和测试。
- Go 引擎内部可保留可复用的多 Tank 数据结构，但不得重新暴露 3/4 人在线匹配。

### 6.3 单人模式

单人模式是纯客户端本地模式，直接复用原版战斗实现，不创建服务端 Battle Actor：

- 一个玩家依次操纵 `Player 1`、`Player 2`、`Player 3`、`Player 4` 四辆 Tank。
- 初始位置、回合/Delay Queue、风力、30 秒计时、移动、完整角度、三种炮弹、弹道、伤害、SS 冷却、地形破坏、坠落和胜负均与原版一致。
- 战斗页面继续使用原版资源、分层 Canvas 和 HUD；仅删除 `Guntanks!` 标题并保留返回大厅入口。
- 单人模式不发送 `match.*`、`battle.*` 或结算请求，不创建 MongoDB battle/event/terrain snapshot，不修改 `wins/losses/draws/games_played`。
- 单人模式退出只销毁本地实例、事件监听器、计时器、动画帧和音频，再返回大厅；不触发投降和重连。
- 单人模式刷新按原版行为重新开始一局，不显示在线对局的 `RECONNECTING`。

必须为单人和在线对战使用互斥页面状态及输入控制器。离开一种模式后，不得残留其键盘监听、定时器或动画影响另一种模式。

## 7. 建议实施顺序

1. 先补充失败测试，复现刷新租约竞态、玩家-Tank 映射丢失和地形恢复失败。
2. 修复 WebSocket 所有权与在线租约生命周期，完成刷新重连闭环。
3. 将原版 Terrain/Tank 移动规则移植到服务端权威引擎。
4. 完成 terrain snapshot 客户端加载、校验和增量事件恢复。
5. 还原角度、发射指示器、武器灯和力度条。
6. 将在线匹配限制为双人。
7. 接入与在线模式隔离的本地单人四 Tank 模式。
8. 重新构建 `guntanks-server.exe`，浏览器硬刷新后执行完整验收。

## 8. 必须补充的测试

### 8.1 服务端

- 同一 session 的旧 WebSocket 在新连接接管后退出，不得删除新连接在线租约。
- 连续快速刷新多次仍只能保留一个当前连接，且能恢复同一对局。
- 真正断网时进入 60 秒重连窗口；主动退出、对局结束和替代连接退出不得进入重连。
- 炸毁 Tank 脚下地形后，Tank 按权威 mask 下落并落在新表面。
- 左右移动遇侧壁、上坡、空洞、地图边界时与原版结果一致。
- Angle 能越过 `90°/180°/270°` 连续变化，弹道方向正确。
- 匹配人数 2 成功，3 和 4 被拒绝且不进入任何队列。

### 8.2 客户端

- 后续 `battle.tank_state` 不会丢失 `myTankId`。
- W/S 调整时 angle 文本和三层圆弧持续更新。
- 1/2/3 的灯光、SS 冷却和 SS 发射后回到 Shot 1 均正确。
- 空格按下从 0 蓄力，松开立即归零；错误、失焦和断线也归零。
- terrain snapshot 加增量事件可重建与断线前逐像素一致的地形。
- 单人模式销毁后不残留监听器；再次进入可创建全新且唯一的游戏实例。

### 8.3 双浏览器端到端验收

1. 两个账户只能进入双人匹配并正常开始战斗。
2. 任一方在对局中连续刷新 5 次，每次均在合理时间内恢复原对局，不出现无限 `Connection lost. Reconnecting...`。
3. 炸出地形缺口后双方显示相同洞口，Tank 会下落，后续移动和炮弹碰撞均依据新地形。
4. 双方分别验证完整角度旋转、三层指示器、三种武器灯和力度条归零。
5. 主动 Leave 仍立即判负并结束双方对局，不进入重连。
6. 单人模式由一个玩家完整操纵 4 辆 Tank，结束或退出后查询用户资料和比赛历史均无任何变化。

## 9. 完成标准

- 上述自动测试全部通过，`go test ./...` 通过。
- 重新生成的 `guntanks-server.exe` 与当前源代码时间一致。
- 浏览器加载当前静态资源，不使用旧缓存。
- 在线战斗规则与视觉以 `C:\GoProject\GunTanks\Guntanks` 为基准逐项比对，不接受“功能近似”。
- 不引入 AI、Bot、3/4 人在线匹配或房间组队功能。
